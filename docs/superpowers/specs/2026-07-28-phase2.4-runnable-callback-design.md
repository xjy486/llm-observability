# Phase 2.4 设计：Generic Runnable / Callback Instrumentation

> 基于 `docs/llm-observability-phase2.4-generic-runnable-callback-development-spec.md`

## 1. 架构概览

复用冻结的 SpanKind：`AGENT / LLM / TOOL / GATEWAY`。不新增 `CHAIN/RUNNABLE/PROMPT/PARSER`。

核心组件：

```
ObservedLangChainRunnable   ← 用户入口 observe_runnable()
├── 创建/复用 AGENT Root（复用 _AgentScope 模式）
├── 注入 LangChainObservabilityCallbackHandler
├── 管理 invoke/ainvoke/stream/astream 生命周期
└── 捕获 Root Input/Output

LangChainObservabilityCallbackHandler  (BaseCallbackHandler, run_inline=True)
├── on_chain_start/end/error → Virtual Run + AGENT Event
├── on_chat_model_start / on_llm_start/end/error → LLM Span (CallbackLLMSpan)
├── on_llm_new_token → TTFT
├── on_tool_start/end/error → TOOL Span
├── on_retriever_start/end/error → TOOL Span (tool.type=retriever)
├── on_retry → Event
└── on_custom_event → Event

CallbackRunRegistry  (dict[run_id, CallbackRunState], threading.RLock)
└── 管理 run_id → state 映射，Parent 传播，Virtual Run
```

## 3. 关键设计决策

### 3.1 Callback Handler 执行模式
- 继承 `BaseCallbackHandler`
- `raise_error = False`，`run_inline = True`（硬性要求：保证 ContextVar 在真实调用线程内生效）
- 所有方法同步 `def`，内部 try/except fail-open

### 3.2 Run Registry
- `CallbackRunState` dataclass：run_id, parent_run_id, run_type, name, context, span, token, context_owner, virtual, sampled, first_token_seen, started_at, ended
- `threading.RLock` 保护增删查，不包裹业务调用
- `run_id` 仅用于 Callback 生命周期关联，禁止映射为 TraceID

### 3.3 Parent 解析
创建真实 Span 时按顺序：
1. parent_run_id → Registry 中对应的 SpanContext.span_id
2. 当前 ContextVar
3. 都无 → No-op

### 3.4 Virtual Chain Run
Chain/Prompt/Parser/Runnable → `virtual=True, context=最近真实 Parent Context`
不创建 Span，仅记录 Event：`langchain.chain.start/end/error`

### 3.5 LLM Callback
- 新建 `CallbackLLMSpan`（不复用 Phase 2.3 `LogicalLLMSpan`，因为数据源不同：serialized dict vs ModelRequest）
- 设置 `logical_llm_span_active=True` 驱动 OpenAI 去重
- `on_llm_new_token` 第一次非空 token → TTFT

### 3.6 Tool / Retriever Callback
- Tool → `Tracer.tool()` 复用
- Retriever → `tool.type=retriever`，默认 `capture_retriever_content=False`

### 3.7 Middleware 去重
- Callback LLM 激活时（`logical_llm_span_active=True`）→ Middleware 注册 Virtual LLM Run，不创建新 LLM
- Callback Tool 激活时（`span_kind=TOOL`）→ Middleware 注册 Virtual TOOL Run

### 3.8 Streaming 生命周期
- `stream()` 返回 generator，Trace 在 generator 耗尽/close/error 时结束
- `astream()` async generator，同上
- 覆盖：正常耗尽、close()、aclose()、GeneratorExit、CancelledError、底层异常

## 4. 测试策略

按 Step 0-8 顺序：
1. Spike 测试冻结行为
2. Wrapper 单元测试
3. Registry/Chain Event 测试
4. LLM Callback + TTFT + Dedup
5. Tool/Retriever Callback
6. Concurrency (RunnableParallel)
7. Privacy
8. Real E2E（FakeChatModel + Real LCEL）
9. Phase 2.1/2.2/2.3 回归

## 5. 禁止事项
- 不新增 SpanKind
- 不把每个 Runnable 变成 Span
- 不把 run_id 当 TraceID
- 不 Monkey Patch Runnable.invoke / CallbackManager
- 不替换用户 Callback
- 不逐 Token 上报
- Callback 异常不进入业务
