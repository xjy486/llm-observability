# Phase 2.1 Closeout 设计文档

> 日期: 2026-07-24
> 目标: 完成 Phase 2.1 Closeout，修复 4 个 P0 和 5 个 P1 问题

## 1. P0-1: Reporter 生命周期自动管理

### 问题
`Observability.init()` 不自动启动 Reporter 的后台 flush 线程，导致 AGENT/LLM span 留在本地 queue 中不被上报。

### 方案
在 `Observability.init()` 中创建独立后台线程，线程内运行独立 asyncio event loop，自动调用 `Reporter.start()`。

生命周期:
- `init()`: 创建后台线程 → 线程内创建 event loop → `Reporter.start()`
- `shutdown()`: 停止接收 → flush → stop → 关闭 session/task/thread → reset state
- 注册 `atexit` handler 做 best-effort flush

### 涉及文件
- `sdk/python/llm_observability/__init__.py` — 增加 `_reporter_thread`, `_reporter_loop`
- `sdk/python/llm_observability/reporter.py` — 增加 `start_sync()` / `stop_sync()` 同步接口

## 2. P0-2: OpenAI Instrumentor 生命周期

### 问题
init 和 shutdown 使用不同的 `OpenAIInstrumentor()` 实例，`_patched` 状态不一致。

### 方案
`Observability` 类长期持有 `_openai_instrumentor` 实例:
- `init()`: 创建实例 → `instrument()`
- `shutdown()`: 同一实例 → `uninstrument()` → 置 None

将 module-level `_tracer` / `_original_create` 改为实例属性，消除跨实例状态问题。

### 涉及文件
- `sdk/python/llm_observability/__init__.py` — 持有 instrumentor 引用
- `sdk/python/llm_observability/instrumentation/openai.py` — 状态移至实例属性

## 3. P0-3: Streaming LLM Span 生命周期

### 问题
`stream=True` 时 `create()` 返回 Stream 对象即立即 `span.end()`，导致 duration 错误、usage 缺失。

### 方案
新增 `ObservedStream` 包装器:
- 包装 OpenAI `Stream` 对象，保持原始迭代行为
- 在以下时机 finalize span: 迭代耗尽 / `close()` / 异常
- 非 streaming 路径保持现有 finally 块行为

### 涉及文件
- `sdk/python/llm_observability/instrumentation/openai.py` — 新增 `ObservedStream` 类，重构 `_patched_create`

## 4. P0-4: Token Ownership 统一

### 问题
LLM Span 和 GATEWAY Span 都记录 total_tokens，SUM 导致双计数。

### 方案
产品级 Token Ownership = LLM Span。Storage 层所有 Token 聚合改为:
```sql
SUM(CASE WHEN span_kind = 'LLM' THEN COALESCE(total_tokens, 0) ELSE 0 END)
```

GATEWAY 可保留 provider observed usage 作为 attributes 调试信息。

### 涉及文件
- `core/storage/db.py` — 修改 `get_trace_summaries`, `get_metrics`, `get_time_series`, `get_trace_detail`

## 5. P1 修复

### P1-1: Nested Trace
已有 active trace 时再次调用 `trace()` 抛 `RuntimeError`。

### P1-2: sample_rate / api_key
- Root trace 创建时做 head sampling: `random.random() < sample_rate`
- `sampled=False` 时 traceparent flags=00，不 enqueue SDK telemetry
- Reporter 请求增加 `Authorization: Bearer <api_key>` header

### P1-3: SDK/Proxy Masking 一致
SDK masking 增加 regex 模式: `sk-*`, `Bearer ...`, `password=...`, `token=...` 等。

### P1-4: Dedup 仍传播 traceparent
Dedup 时仍注入 traceparent + ownership marker，只跳过 span 创建。

### P1-5: 内部 Header 不泄露
Proxy 转发时 strip: `X-LLM-OBS-Span-Role`, `X-Session-Id`, `X-User-Id`, `X-App-Name`, `X-Business-Scene`。`traceparent` 保留（重新生成后传播）。

### 涉及文件
- `sdk/python/llm_observability/tracer.py` — nested trace 检查 + sampling
- `sdk/python/llm_observability/reporter.py` — api_key auth
- `sdk/python/llm_observability/utils/masking.py` — regex masking
- `sdk/python/llm_observability/instrumentation/openai.py` — dedup propagation
- `proxy/handler.py` — header stripping
- `proxy/config.py` — sensitive_headers 更新
